# 可直接交给 Codex 的后续开发指令

你是一名资深 Rust 全栈工程师。当前工作区为 `PicCove（图湾）` 的原型仓库。先阅读 README.md、docs/ARCHITECTURE.md、docs/ROADMAP.md，理解现有代码与尚未完成模块，再分阶段实施。目标不是一次性生成大量不可运行代码，而是每一步可构建、可测试、可验收。

技术栈：Rust stable / Axum 0.8 / Tokio / SQLx 0.8 / PostgreSQL 16；React 19 / TypeScript / Vite；Redis（后续）；对象存储统一接口，初期 local + S3；未来 Tauri 2 跨端。

**第一轮任务：**

1. 先在实际环境中安装项目依赖并执行 `cargo fmt --check`、`cargo check`、`cargo test`、`pnpm install`、`pnpm build`，修复全部编译/类型错误。不得隐藏失败。
2. 补充 API、数据库迁移和前端的基础测试，至少覆盖未认证上传、损坏文件、超限文件、非法尺寸、404、成功上传及图片列表。
3. 在不破坏现有 API 的前提下，将 API 项目模块化为路由、handler、service、repository、storage、auth、config、error；避免过度工程化。
4. 使用现代 UI 组件创建清晰的图库界面，包括批量拖拽上传、进度、缩略图、多选、搜索和反馈；不得把开发令牌机制当成正式鉴权实现。
5. 新增 `StorageProvider` trait，本地实现作为第一阶段默认驱动，并定义 S3 驱动集成测试接口；密钥加密存储，只在服务端读取。
6. 给出明确的后续迁移路径：真实用户登录、多租户、预签名直传、异步处理、私有访问、计量、支付和审计。

安全约束：

- 所有客户端输入不可信，不能仅靠 Content-Type 和扩展名判断文件类型。
- 验证授权主体、租户、资源关系，必须防 IDOR。
- 后端必须限制上传体积、尺寸、请求频率、超时和内存消耗；不可信图片解码需隔离且限制资源。
- 拒绝默认上传可执行 SVG/HTML；凭证不得出现在客户端代码、日志、仓库或构建产物。
- 采用数据库事务、幂等键、任务重试与残留对象清理。上传成功状态只能由服务端实际检查对象后确认。
- 优先保持模块边界与 API 稳定，提供接口文档和可复现实测命令。

输出要求：每个迭代先列本轮范围；直接修改源代码；执行验证并报告真实结果；列出已经完成、仍未完成和技术风险。不要声称原型具备商业生产能力。
