# AI 生图与图片审核实施规格

状态：2026-10-25 用户确认实施；源码实现与隔离验证完成，未部署。本文是本次变更的范围与验收依据。

## 接入与范围

- 只调用管理员配置的 API，不判断订阅、中转或计费来源。生图和审核分别配置地址、密钥及模型；密钥只保存在服务端，读取配置不返回密钥，留空更新保留原密钥。
- 生图采用 Responses API 的 image_generation 工具；主对话模型与图片工具模型分别指定。审核采用 OpenAI 兼容 Chat Completions 视觉模型和严格结构化结果，不直接适配云厂商专有接口。
- API 未配置时功能关闭；启用审核后仅覆盖新增图片，不回扫历史库存。不开启联网搜索、语音、文件分析、局部涂抹或其他协议适配。
- 网页提供历史会话、图文消息、上传参考图、连续生图与改图。结果保存为新图片，不覆盖原图，默认私有，可沿用图库公开分享功能。
- 连续对话显式重传按顺序保存的文本历史，并附带本轮上传的参考图或最近一张对话图片；不依赖上游 `previous_response_id`，请求使用 `store=false`。供应商必须支持 Responses 图片输入与图片工具。每轮最多一张、每个会话最多 100 轮、提示词最多 4000 字符；仅文字回复不扣图片额度，全站最多同时运行 4 个生成任务。
- 普通登录用户默认 UTC 每日 20 张、同时 1 个生成任务；额度及并发可配置。生成和改图共用额度，失败不扣本站额度，进行中任务预占额度。管理员免生图额度，审核白名单普通用户不免额度。

## 审核与访问

- 覆盖新增上传（含导入）、改图参考图及 AI 生成结果。复用图片存储与 PostgreSQL 持久任务模式；外部网络请求不能持有 uploads 锁。
- 默认先发后审，可切换先审后发。待审与审核失败：先发后审遵循原公开状态；先审后发仅本人和管理员可读。
- 发布模式在图片入队时记录，修改配置作用于后续任务，不改变已入队图片的发布模式。审核前主动删除图片可能使任务因原图不存在而失败，不会抹掉已经认定的违规记录。
- 明确色情、暴力、血腥、中国政治人物敏感均阻止普通用户查看或下载，并计违规；同图多类别只计一次。政治人物类别不豁免新闻、历史语境。
- 疑似结果阻止普通用户访问，但不计数。管理员可查看、确认违规或撤销误判。错误与格式不合规不是违规，有限重试（最多 3 次）后标记审核失败，可手动重试。
- 原图、缩略图、对话图片引用、公开开关均执行审核访问规则；禁止通过对话上下文重新发送被拦截的参考图。先发后审存在短暂公开窗口。
- 未审核的参考图先完成审核再送生图服务；审核故障时等待或拒绝生成，不将失败当作通过。生成完成后的图片仍异步审核。
- 管理员默认免审，普通用户可加入审核白名单；新任务免审，不清除既有违规或封禁。白名单仅跳过本站审核，不影响上游限制。

## 计数、封禁与纠错

- 上传、参考图、AI 生成结果明确违规均计入所属用户；同一用户相同内容哈希只计一次，任务重试、重复回调和重复上传不得重复计数，删除图片不能清零历史次数。
- 默认累计 5 次自动封禁，阈值可配置。支持手动封禁和解除；管理员账号不自动封禁。
- 内容封禁独立于既有 disabled：保留登录和查看原因，禁止上传、生图、改图、新增公开分享；保留正常历史外链。
- 撤销误判扣回该内容计数。只在次数降到触发阈值以下时解除对应自动封禁；不解除手动封禁。手动解封保留次数，下一次新增违规可再次触发自动封禁。
- 白名单不自动解除已有封禁，也不免除正常用户生图用量限制。

## 持久化与故障语义

- 审核状态、结果、尝试次数和下一次重试时间写数据库；重启恢复审核任务。审核最终处置与违规计数在同一事务内完成。
- 生图任务与对话持久化，刷新后可查看进行中和结果。重启后不盲目重发可能已被上游计费的生成请求，标记中断失败并释放本站预占额度。
- 所有会话和参考图片检查用户归属；API 地址仅管理员设置，禁用请求重定向，限制响应大小、超时、提示词和上下文尺寸。日志及浏览器不暴露供应商密钥或原始上游错误。
- 生成内容视为不可信数据，图片仍经过现有图片格式、大小、容量和落盘校验。模型结果必须符合枚举与结构，不因响应解析失败放行。

## 已知限制

视觉模型不等于专用政治人物库，会误判或漏判；严格计数会把模型生成失误计入用户违规。首次不承诺任意“OpenAI 兼容”服务支持 Responses 图片工具，须用目标服务实际联调。

## 使用入口

1. 管理员进入“系统设置 → AI 生图与审核”，分别填写两组基础地址、密钥和模型。基础地址包含供应商所需的 `/v1` 前缀，不包含 `/responses` 或 `/chat/completions` 后缀。
2. 配置生图的对话模型和图片工具模型；如需审核，配置视觉模型后开启新增图片审核。密钥留空保存代表保留原值；清空生图基础地址可暂停新生成，取消审核开关暂停审核。
3. 用户进入“AI 图片对话”，上传参考图并发消息；参考图未通过审核时任务会失败且不扣图片额度，审核完成后可重新填写上一条提示词与参考图重试。
4. 管理员在“图片审核”查看结果、重试失败任务、确认违规或撤销误判；在“用户与配额”查看违规次数、设置免审白名单和手动封禁／解除。

部署需同时更新 API 和 Web，并由新 API 启动执行 `0009_ai.sql`。本次不执行生产迁移或部署；已审核数据不能直接交给忽略审核状态的旧 API 提供访问。

## 2026-10-26 真实联调与多角色复核

### 连续改图原因与修复

上一轮仅发送响应 ID 时，上游返回要求重新上传图片的文字，没有出图。[Sub2API 转发代码](https://github.com/Wei-Shaw/sub2api/blob/main/backend/internal/service/openai_gateway_forward.go)对部分非 WebSocket v2 OAuth 路径移除 `previous_response_id`；[Codex 请求转换](https://github.com/Wei-Shaw/sub2api/blob/main/backend/internal/service/openai_codex_transform.go)将 OAuth 请求改为 `store=false`。这与现象一致，但没有检查用户实际部署版本或账号类型，不能断言其具体内部执行路径。

本站现改为重传本地文本历史和必要图片，保留全部历史图片的归属、删除、审核状态校验，避免借对话重新发送受限图片。本轮上传图优先；没有新上传图时沿用最近的生成图／参考图，纯文字轮次不会丢失该图。限制：不重传全部旧图，不能保证“回到第 N 张图”这样的历史图片定位；当前主流程是连续修改最近一张图。

### 真实网页联调

使用独立 PostgreSQL 与 Chromium，管理员、Alice、Bob、样本上传用户分别登录；Alice 与 Bob 的请求真实并行，不共享浏览器会话。实际调用用户授权的 Sub2API：对话与审核模型 `gpt-6.1-sol`，图片工具 `gpt-image-2`。

- 网页保存两组 API 配置，焦点切换不清空未保存密钥；保存后输入框清空，读取接口不返回密钥。
- Alice：蓝色杯子 → 不重新上传改为红色 → 纯文字询问代号 → 改为绿色 → 上传另一张杯子照片并改为黄色。四次图片输出成功，文字能记住“海风”；浏览器完成图片下载与解码。
- Bob 同时进行纯文字对话，跨轮记住“橘子”；读取 Alice 会话返回 404。刷新后从历史恢复会话与图片成功。
- 真实审核后违规计次、普通用户访问违规原图返回 404、管理员可读、网页手动封禁／解封、白名单开关与新增图片免审均通过。
- 浏览器验证中发现 AI 页移动端长会话标题撑宽网格，改为明确的单列收缩布局；失败消息“重新填写提示词”也补上请求中禁用。
- 首次脚本假设默认密码登录，实际页面默认 Passkey，修正测试选择器；一次 Chromium 启动崩溃后改用任务非特权身份运行正常。白名单 checkbox 是异步受控状态，测试改为点击后等待后端及界面更新，没有重复生图。
