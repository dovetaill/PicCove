## 一、核心结论速览（四大维度）

在刚完成前后台 UI 重构的基础上，我们对 `apps/api`（Rust 后端与 `piccovectl` 运维 CLI）、`admin`（React 19 工作台）、`apps/android`（原生安卓端）、`deploy` / `infra` / `scripts` / `.github` 及全套文档与测试进行了地毯式双盲交叉审计，核心发现归纳如下：

### 1. 潜在漏洞与可靠性缺陷（共 10 项确认，含 5 项高优 P0/P1）
- **慢速上传全局锁饿死全站（Slowloris 级可用性漏洞）**：`upload_image` 在读取网络 `multipart` 请求体**之前**就获取全局唯一互斥锁 `state.uploads`（`main.rs:659`），而公开外链读取 `serve_image`（`main.rs:1208`）与缩略图 `thumbnails::serve`（`thumbnails.rs:32`）竟也争抢同一把锁。任意单用户的慢速上传或半开连接即可卡死全站所有访客外链和图库加载。
- **双层反代导致 IP 限流坍缩为“全站共享 20 次/分”**：生产拓扑为 `宿主机 Nginx -> Docker web 容器 Nginx -> api 容器`（`deploy/nginx.conf:19`），`api` 读到的 `ConnectInfo(peer).ip()` **永远是 `web` 容器的内网 IP**。任何外部脚本每分钟发 20 次无效短密码请求（`rate()` 甚至先于密码长度校验执行），即可把包括管理员密码登录和 Passkey 登录在内的全站用户全部锁死 `429`。
- **次盘离线或单张脏记录导致全站无法启动**：`bootstrap` 在绑定 HTTP 端口前遍历 `deleted_at IS NOT NULL` 记录并强制清理，一旦某块历史次要挂载盘离线或旧迁移副本校验不符，整站 API 直接崩溃退出，连主盘正常图片和后台修复界面都无法打开（`main.rs:1343-1351`）。
- **备份与升级的“误伤停服”隐患**：
  - `piccovectl backup` 在停止写入前检查外盘范围、**漏备本站依赖的 `compose.override.yml`**（含宿主机 AI 网关映射与外部存储挂载），且临时容器清理报错会跳过恢复启动步骤，直接把生产服务留在停机态（`ctl/mod.rs:1085-1165`）。
  - `piccovectl update` 先停服再编译镜像导致停机窗口过长；更危险的是**新版本已通过健康检查并写完 `release.json` 后**，若清理无用旧镜像失败，仍会跳入统一错误分支反手停掉健康的新容器，并留下 `.piccove-update-pending.json` 锁死 `start`（`ctl/mod.rs:1008-1056`）。
- **AI 状态机与软删除口径缺口**：AI 生图落盘与消息完成分属两次独立提交，且失败回写用 `let _ =` 静默吞错（可能永久卡死会话并泄漏额度）；文件落盘失败留下 `deleted_at` 残留行计入配额；前端删除遇 `500`/断网时提前删本地历史、审核台静默吞错伪造零尺寸图片对象。

### 2. 可删除、合并与精简的冗余资产（7 类瘦身项）
- **发行包信息泄露与膨胀**：`scripts/release.py:121` 将整个 `docs/` 原样打入公开 Release 压缩包，导致包含真实服务器 IP、域名、证书路径与内网 AI 网关的 `DEPLOY-tu.jpggg.com.md` 以及内部审计稿随每次公开发版分发。
- **重复接口与双份面板**：后端 `/api/v1/admin/storage` 与 `/api/v1/storage-locations` 功能重叠；前端 `overview-page.tsx` 与 `settings-page.tsx` 复制粘贴了 ~160 行完全相同的版本检测/升级/重启状态机与弹窗代码。
- **模板残留与僵尸文件**：`admin/README.md` 仍是 Metronic 的 Supabase 教程；`admin/documentation.html`、`admin/nginx.conf`、`apps/web/` 空壳目录、`infra/compose.yml` 中根本未使用的 `redis:7-alpine`、`admin/src/components/ui/` 下 18~21 个零引用组件（约 2,200 行）、`admin/public/media/app/` 下 18 个未引用模板图标，以及 Git 跟踪的 `artifacts/ui-review/`（2.0 MiB）均可清理或收口。

### 3. 现有功能与工程性能改进（7 项体验升级）
- **首屏包体与缓存优化**：当前前端单 chunk 高达 **903.9 KB JS + 150.5 KB CSS**，且 `deploy/nginx.conf` **未开启 `gzip`**（仅开 `gzip` 即可降至 **265 KB + 22 KB**，配合路由懒加载首屏再降 60%+）；公开原图与缩略图一律 `Cache-Control: no-store`，每次翻页全量重传，可改为支持受控 `ETag` / `304` 条件重验证。
- **消灭批量 N+1 与队列膨胀**：前端批量移动/公开/删除最多串行发 48 次请求，补齐轻量批量接口可降为 1 次请求；上传队列已完成记录永久堆积 IndexedDB 导致顶栏计数失真与“复制本次链接”混入旧图。
- **打通 AI 会话管理与 Worker 吞吐**：补齐 AI 会话重命名/删除、解除“删旧图即永久报废整段会话”的死板限制；消除审核 Worker 每张图固定 `sleep(2s)` 的空等延迟。
- **Android 客户端对齐现代后端**：网格改读服务端鉴权缩略图（省去每页最高数百 MB 的原图流量）、分享改用带后缀规范外链 `url`、上传直接带 `album_id`、局部 `PATCH` 不再覆盖另一端改名。

### 4. 契合产品定位的 4 项高价值新增功能
立足“自用与小范围开放的轻量现代图床”，不搞多租户计费、微服务或 Redis 重型基建，精准补齐 4 个闭环能力：
1. **2FA 一次性恢复码 + 管理员重置用户二步验证**（解决丢手机永久锁死账号的运维死结）。
2. **个人上传 API Token（兼容 PicGo / ShareX / CLI）**（图床高频刚需：Typora/Obsidian 写文截图一键上传拿直链）。
3. **可选的上传清除 EXIF / GPS 定位隐私开关**（默认保留无损原图，勾选后自动剥离拍摄经纬度与设备隐私元数据）。
4. **带有效期与可随时撤销的临时分享链接**（无需把私密照片永久设为公开，即可生成 1 天 / 7 天有效期的受控分享链接）。
